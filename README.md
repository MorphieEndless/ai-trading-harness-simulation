# AI Trading Harness

单 Agent、容器化的加密资产**模拟盘**交易系统。
行情是真的，成交价按真实盘口撮合，但账户里的钱是虚拟的——不可能亏掉真人一分钱。

部署位置：`YOUR_SERVER_IP`（香港） · 面板：`https://trader.example.com/`

> 本系统为单 Agent 容器化模拟盘交易环境。生产部署前请确保完成 `.env` 与模型策略配置。

## 一、架构

```
                    ┌──────────────────────────────┐
   浏览器 ──CF──► nginx ──BasicAuth──► trader-brain │
                    │  :443 → 127.0.0.1:18080      │
                    └──────────────────────────────┘
                                  │
        ┌─────────────────────────┴──────────────────────────┐
        │  trader-brain                       （大脑，只读根FS）│
        │  · 心跳调度器：三类唤醒 + 睡眠（见第十八节）      │
        │  · LLM 循环：思考 → 调工具 → 观察 → 再思考           │
        │  · 本地工具：工作区文件读写 / Landlock 受限 shell     │
        │  · 事件总线：内存环形缓冲 + append-only JSONL        │
        │  · WebUI：SSE 实时日志 + 账户面板 + 人工干预         │
        │  · 叙事层：读事件流 → 重写成角色口吻的日志（单向）    │
        └───┬──────────────┬───────────────┬─────────────────┘
            │              │               │
    ┌───────▼──────┐ ┌─────▼────────┐ ┌────▼──────────────┐
    │ mcp-market   │ │ mcp-paper    │ │ exa (远端托管)     │
    │ 只读行情      │ │ 模拟盘引擎    │ │ 联网搜索           │
    │ 无 key       │ │ SQLite 账本   │ │ mcp.exa.ai/mcp    │
    │ 9 个工具      │ │ 17 个工具     │ │ 2 个工具           │
    │ 物理不可能下单 │ │ 风控 + 睡眠配额│ │ 匿名可用           │
    └──────────────┘ └──────┬───────┘ └───────────────────┘
                            │
                    data/db/trader.db
                  （★ 此目录不挂进大脑容器）
```

**为什么这样切分：**
- 行情与交易分离。行情容器里没有任何 key，代码里也没有下单路径——就算 Agent 被完全策反，
  它在那个容器里能做的上限就是读公开行情。
- 纸面账本 `data/db` **不挂载进大脑容器**。Agent 就算拿到 shell，也改不了持仓和现金，
  绕不过风控。
- 风控是代码不是提示词。`mcp-paper` 里硬编码仓位上限、持仓数上限、日亏熔断、手续费滑点。

## 三、日常操作

```bash
cd /opt/ai-trader

docker compose ps                    # 看状态
docker compose logs -f brain         # 看大脑日志
docker compose restart brain         # 重启大脑
docker compose down                  # 全停
bash setup.sh                        # 改完配置后重新部署（含 nginx）
bash set-llm.sh <url> <key> <model>  # 换主模型，一行搞定bash set-subagent.sh --interim       # 启用子代理（用现有端点的便宜模型）
bash set-subagent.sh --off           # 关闭子代理
bash reset-paper.sh                  # 清空模拟盘（会二次确认）
bash set-persona.sh --show           # 看当前声音卡 / --clear / --example A
bash runtests.sh all                 # 十一组测试（只有 cap 花一点 token）
bash push.sh                         # 列出本地改了但还没推上去的文件
bash rebuild.sh                      # 重建 + 验收（替代手敲 docker compose up -d --build brain）
bash rebuild.sh --check-only          # 只查：现在这个容器烤的是磁盘上那份吗
```

**唤醒与睡眠**（不用改文件，面板上直接调）：

```
面板右栏「唤醒策略与睡眠」→ 间隔 / 每小时上限 / 冷却 / 阈值 / 睡眠开关
面板顶栏睡眠胶囊            → 一眼看它是醒着还是睡着、欠多少睡眠
面板「叫醒 / 去睡」按钮      → 人工干预
```

想改**种子**（面板那份不存在时才会读）：`config/wake_policy.json`。
注意它不是热加载 —— 要删掉 `/data/logs/wake_policy.json` 再重启才会重新播种。

**改完东西怎么上线：**

```bash
bash push.sh <文件...>               # 推到 165
bash rebuild.sh                      # 重建（brain/ 和 static/ 是烤进镜像的）+ 当场验收
```

> **⚠️ 这两步必须串行。** 重建读的是**磁盘上当时**的源码；
> 如果两条命令并发发出，烤进镜像的是旧代码，而 `docker compose ps` 看起来一切正常。
> 这个坑 2026-09-27 被踩了**四次**，每次都是侥幸（push 比构建快）。
> **所以别手敲了，用 `bash rebuild.sh`** —— 它构建完会拿**构建前**的磁盘 md5
> 跟容器里逐个比，不一致就红；也会拦住"一轮心跳正在跑"的重建
> （那种重建会静默踩断一轮，场上不留痕迹）。
>
> **⚠️ 只推不重建等于没改** —— 大脑的代码是构建时烤进镜像的。
> 例外：`config/` 里的人类文件（`persona.md`、`character.md`、白名单）是热加载的，
> 推上去下一次心跳就生效，不用重启。
>
> **⚠️ 改过面板（`index.html`）一定要跑一次** `bash runtests.sh frontend`。
> 那次"整页显示连接中"的事故就是改面板改出来的，两秒钟的检查能永久兜住。

改 `.env` 后生效方式：`docker compose up -d --force-recreate brain`
（`mcp-paper` 的风控参数和**睡眠配额**改了要重建 `mcp-paper`）。

## 五、风控（在 `mcp-paper` 内强制执行）

| 参数 | 默认 | 说明 |
|---|---|---|
| `RISK_MAX_POSITIONS` | 5 | 最多同时持有几个币 |
| `RISK_MAX_POSITION_PCT` | 0.25 | 单币种市值 ≤ 总权益的 25% |
| `RISK_MAX_DAILY_LOSS_PCT` | 0.06 | 当日亏 6% 熔断，禁止开新仓 |
| `RISK_MIN_NOTIONAL` | 20 | 单笔最小金额（USDT） |
| `RISK_FEE_BPS` | 10 | 手续费 0.1%/边 |
| `RISK_SLIPPAGE_BPS` | 5 | 滑点 0.05%/边 |

**往返成本 = 0.30%**。任何期望收益低于这个数的策略长期必亏，提示词里已明确写死告诉 Agent。

另有**后台止损巡视线程**（每 30 秒）：到价自动平仓并写入事件流，
所以两次心跳之间的暴跌也能被接住，不依赖 Agent 醒着。

### 睡眠配额（同一容器、同一个理由）

| 参数 | 默认 | 说明 |
|---|---|---|
| `SLEEP_MIN_HOURS_PER_DAY` | 6.5 | 滚动 24 小时内最少睡多久 |
| `SLEEP_MAX_SINGLE_HOURS` | 11 | 单次最长，到点强制叫醒 |
| `SLEEP_MAX_AWAKE_HOURS` | 17.5 | 连续清醒上限（= 24 − 6.5），到点强制入睡 |

**它和风控放在同一个 SQLite 里，因为理由完全相同：**
`data/db` 是唯一没挂进大脑容器的目录，所以 Agent 改不到。
放 brain 能写到的任何地方（包括 `/data/logs/`）它都能一句 shell 改掉 ——
详见第六节那两条「不隔离」和第八节的故障说明。

## 六、隔离边界（Agent 就算拿到 shell 也越不过去）

| 事实 | 怎么做到的 |
|---|---|
| 读不到 LLM key | 三层：子进程环境变量白名单 + Landlock 拒绝 `/proc` + brain 进程 non-dumpable |
| 读不到叙事层手账 | `run_shell` 的子进程挂着 Landlock 规则，`/data/logs` 不在白名单里 |
| 改不了账本 | `data/db` 根本没挂进大脑容器 |
| 改不了睡眠配额 | 同上 —— 配额和风控放在同一个 SQLite 里，理由相同 |
| 写不到宿主机 | 大脑容器根文件系统 `read_only`，可写点只有 `/data/workspace` 与 `/tmp` 的 tmpfs |
| 提不了权 | `cap_drop: ALL` + `no-new-privileges`（Landlock 也顺带要求这一条） |
| 下不了真单 | 没有任何交易所 API key，模拟盘代码里也没有真实下单路径 |
| 越不了工作区（`fs_*`） | `fs_*` 工具做 realpath 校验 |
| 越不了工作区（`run_shell`） | Landlock 文件系统规则，见下 |

### `run_shell` 的 Landlock 沙箱（2026-09-27 补）

在这之前，`run_shell` **只设了 `cwd`**。它和 brain 进程同一个 uid（10001），
而 `/data/logs` 是 rw 挂进大脑容器的 —— 所以那句话是成立的：

> **brain 能读能写的地方，`run_shell` 也能读能写。**

这条漏口有两个后果，第二个是这次动手时**才**发现的，比记在案的那个更严重：

1. **叙事层的「单向性」在 shell 这条路上是漏的。** 它一句
   `cat /data/logs/journal.md` 就把叙事层的输出读回了自己的操盘上下文。
   第十三节写的"手账刻意放 logs，因为工作区是 Agent 能 `fs_read` 到的地方"——
   那句话只在 `fs_*` 这条路上成立。
2. **`/proc/<pid>/environ` 里躺着明文 `LLM_API_KEY`。**
   `env={...}` 清空的是**子进程要拿到的那份**；brain 自己的初始环境块还在内核里，
   路径就是 `/proc/1/environ`，同 uid 可读。实测：

   ```
   $ cat /proc/1/environ | tr '\0' '\n' | grep KEY
   LLM_API_KEY=sk-sC36...ZfqF0u
   ```

   「密钥只在 brain 进程环境里，Agent 拿不到」——这句话当时**写在本文档里当保证**，
   其实只挡住了 `env` 这一条路。和第一条是同一个错误：**把约定当成了物理保证。**

**现在的做法**（`brain/trader/sandbox.py`，改动集中在 `tools_local.py` 的 `run_shell`）：

```
run_shell
  └─ python3 sandbox.py --workspace /data/workspace -- /bin/sh -c "命令"
       ├─ 换掉环境变量（白名单只有 PATH/HOME/PWD/TMPDIR/LANG/TERM）
       ├─ prctl(PR_SET_NO_NEW_PRIVS)
       ├─ landlock_add_rule：工作区/Tmp 全权、系统目录只读、/dev 读写
       └─ landlock_restrict_self → execve
```

白名单只有这些，**其余一律 EACCES**：

| 目录 | 权限 |
|---|---|
| 工作区、`/tmp` | 全权 |
| `/usr` `/bin` `/sbin` `/lib*` `/etc` `/opt` `/app` `/sys` | 只读 + 可执行 |
| `/dev` | 读写（`/dev/null`、`/dev/urandom`） |
| **不在名单里的** | **`/data`（含 `/data/logs`）、`/proc`、`/root`、`/home`、`/var`…** |

为什么是 Landlock 而不是 chroot / bubblewrap：容器 `cap_drop: ALL`，
没有 `CAP_SYS_CHROOT`；unprivileged userns 也被 Docker 的 seccomp 拦着
（实测 `unshare(CLONE_NEWUSER)` → EACCES）。**Landlock 是这里唯一可用的那把刀** ——
非特权 LSM，只要 `no_new_privs`，内核 5.13+。实测线上内核 6.1.0 → ABI 2。

`/proc/environ` 那条另有第二道防线：brain 启动时 `prctl(PR_SET_DUMPABLE, 0)`。
进程不可 dump 之后，`/proc/<pid>/` 下的 `environ`/`maps`/`mem` 对同 uid 的兄弟进程
就要求 `CAP_SYS_PTRACE` 了。两道一起上是有意的 —— Landlock 将来要是因为内核降级
没挂上，这条还在。

> ### ⚠️ 还有一条要如实说清楚的：Landlock 管不到 `stat`
>
> Landlock 约束的是**内容访问**（open/read/write/mkdir/rmdir…），
> **不约束 `getattr`**。所以子进程仍然 `stat` 得到名单外的路径：
>
> ```
> $ stat /data/logs
>   File: /data/logs      Size: 4096   Inode: 655411     ← 成功
> $ ls /data/logs
>   ls: cannot open directory: Permission denied          ← 拒绝
> $ head /data/logs/journal.md
>   Permission denied                                     ← 拒绝
> ```
>
> 也就是说：它知道手账**存在**、多大、什么时候改过，**但读不到一个字节**。
> 同理 `pathlib.Path("/data/logs").exists()` 返回 `True`。
> 这条没法用 Landlock 修（那是内核 v6 的 getattr 支持范围），
> 直说比假装它不存在好。

> ### 关于「什么东西能放哪」的那句话
>
> `/data/logs` 是 rw 挂进 brain 的，而且 brain 与 shell 子进程同 uid。
> 所以判断一个约束该放哪时，最该先问的还是那一句：
> **这个约束能不能放在 Agent 写得进去的地方？** 不能，就得进 SQLite。
> 睡眠配额就是这么定下来的（第十八节）。Landlock 没有改变这个判断 ——
> 它只是把"读得到"这一半补上了；写那一半本来就该靠"根本不挂进去"。

## 七、如果以后要接实盘（不建议轻易做）

当前架构刻意留了一个"人类专属开关"的位置。若要接真钱，务必：
1. 风控开关（如 `ALLOW_LIVE_TRADING`）做成**环境变量**，任何 MCP 工具都改不了它，
   prompt injection 也撬不动。
2. API key **关掉提现权限**，只留交易权限，并绑定 IP 白名单。
3. 先用 Binance **测试网**跑一段时间，但心里清楚：测试网撮合与真实流动性无关，
   测试网"盈利"不等于实盘能盈利。
4. 盯盘 MCP（无 key、只读）与交易 MCP **继续分离**，不要合并成一个权限很大的 server。

## 八、故障排查

| 症状 | 原因 / 处理 |
|---|---|
| 面板打不开 | DNS 没加 / CF 未开橙云。检查 `getent hosts trader.example.com` |
| 面板 502 | `docker compose ps` 看 brain 是否在跑 |
| 面板 401 循环 | `.env` 里 `WEBUI_PASSWORD` 改了但没重跑 `setup.sh`（nginx 的 htpasswd 要同步） |
| 一直不交易 | 面板看 `last_error`。多半是模型端点不通或工具调用不被支持 |
| MCP 报 421 | 服务名没进 `MCP_ALLOWED_HOSTS`（DNS 重绑定保护） |
| 容器 Permission denied | 构建上下文文件权限是 600。Dockerfile 里的 `chmod -R a+rX /app` 已兜住 |
| 日志里满是 `$0.30\%$`、`$83{,}600$` | 模型在写 LaTeX。**改提示词，不是改渲染** —— 见第十三节的"那些 `$` 和 `\`" |
| 日志里美元符号被吃掉 | `texLite` 的正则放宽了。`TEX_HINT` 的最后一个分支刻意不含 `:` / `-` / 空格 |
| 在服务器上跑 `bash push.sh` 报 `Permission denied` | 无参数模式会在远端再 ssh 一次自己，而服务器没有自连 key。**从工作区跑**，或显式 `bash push.sh <文件...>` |
| 叙事层一篇都不写 | `NARRATOR_ENABLED` 是否为 true；再确认 `NARRATOR_MAX_GAP`（0 会变成每轮都写） |
| 叙事层重复写同一段 | `journal.md` 读不到 → 跨重启的时间恢复失效。检查 `NARRATOR_JOURNAL_FILE` 的挂载 |
| 日志里的报错被重复列了 N 遍 | 已处理（同类事件压成「×N」）。若又出现，看 `_digest` 里的去重段 |
| 调度器每 30 秒重试、日志刷满 traceback | 代码里有运行时才暴露的错（如 `NameError`）。先跑 `bash runtests.sh lint` |
| **面板一直显示「连接中」、日志永远空白** | **`index.html` 里 JS 有语法错误，整段 `<script>` 没被解析**，三行初始化都没跑。后端一切正常，所以从数据侧看不出来。跑 `bash runtests.sh frontend` —— 2026-09-27 真出过一次（`esc(` 少一个右括号） |
| **某一块永远停在初始占位文本（如行情卡一直「等待取价…」）** | **`$("xxx")` 少写 `#`**。`$` 是 `document.querySelector`，没有 `#` 就按**标签名**找 → `null` → 那个渲染函数在第一行 `return` 了，一次都没画过。数据其实是好的，所以从后端和日志都看不出来。跑 `bash runtests.sh frontend` 的 **[3b]** —— 2026-09-27 真出过一次（`renderMarket` 里的 `mkBox` / `mkMeta`） |
| **日志列事件时满屏 `{"reason": "…"}`** | 后端发了新的事件种类而 `renderEvent` 的 `switch` 没配，掉进 `default`。现在 `default` 会摊成「键：值」，但正解还是补一个 `case`（照着 `price_trigger` 那几段写），并在 `test_frontend.py` 的 **[7]** 里加一条 |
| **日志/手账断在半句上** | 大概率是 `finish_reason=length`（被 `max_tokens` 砍断）。看容器日志里的 `叙事层这一篇被 max_tokens 截断了`，或 `/api/health` 的 `narrator.truncated_count`。**200 字以上的一篇断句，不要靠肉眼找** —— 事件流里的 `finish_reason` 与面板的 `✂` 就是为它准备的 |
| **工具参数挤成一条长线、中间夹着一堆 `\n`** | 后端发的是 `json.dumps` 的紧凑 JSON，换行是**字面的两个字符**；`pre-wrap` 对它没用。面板的 `fmtCallArgs` 负责摊开它 —— 若又挤了，看 `test_frontend.py` 的 **[8]** 和 **[10]**（[10] 需要 `pip install quickjs`） |
| **点「展开」什么都没多出来** | 折叠提示只在**真被裁掉**时才出现（`markClip`）。若短卡也顶着提示，先跑 `bash runtests.sh frontend` 的 **[9]** |
| **行情卡的价不动 / 一直显示缓存** | 先看旁注：`缓存 HH:MM · 刷新失败` 表示 `/api/market` 打不通（浏览器控制台看具体错）。`取价 N 分钟前` 表示后端那个 30 秒轮询停了，看 `/api/health` 的 `prices_age_seconds` |
| **日志里刷 `价格监控异常：JSONDecodeError`** | MCP 把列表返回值拆成了多个 block，`\n` 拼起来不是合法 JSON。已修（`mcp_hub._join_blocks`），若复现看 `test_hub.py` |
| **期待「每 N 分钟醒一次」但它没醒** | 兜底的语义是**「最长沉默」不是节拍**：期间只要有人类阈值或自唤醒发生过，那次兜底就自然被跳过。想知道这轮是谁叫醒的，看事件流里的 `beat_start.trigger` 或面板的唤醒统计 |
| **唤醒策略改了没反应** | 面板改的写进 `/data/logs/wake_policy.json`，下一次判定生效（不用重启）。若整份策略丢了，看仓库里的 `config/wake_policy.json` 种子有没有被读到 |
| **面板显示「⚠ 睡眠账本不可达」** | `mcp-paper` 挂了或没重建。此时调度会按"清醒"降级（不会卡死），但睡眠配额不生效 |
| **一天最少睡 6.5 小时没生效** | 配额在 `mcp-paper` 里。改过 `.env` 的 `SLEEP_*` 之后要重建 **mcp-paper**，不是 brain |
| **它一直不睡 / 一直不醒** | 不睡：`sleep` 只警告不拦，可能是它自己不想睡；硬闸在连续清醒 17.5h 才响。不醒：单次上限 11h 会强制叫醒，若没醒看 `_sleep_snapshot` 的 `must_wake_now` |
| 想重来 | `bash reset-paper.sh` |

## 十、成本说明（重要，请务必看完）

Agent 循环的成本结构是：**每一步都要把「系统提示词 + 34 个工具定义 + 全部历史消息」
重发一遍**。成本 ≈ 单步上下文 × 步数，不是「一问一答」那么简单。

### 实测的固定开销（这是"底价"）

拿线上同一份 system prompt + 同一批工具发一次真实请求，读回来的 `prompt_tokens`。
**2026-09-27 重测：**

| | 字符 | |
|---|---|---|
| system prompt | 5,652 | |
| ├ `base_prompt` | **4,866** | 占 system 的 **86%** |
| ├ `persona.md`（声音卡） | 316 | |
| └ `closing` | 165 | |
| 工具定义 32 个 | 12,841 | 最肥的一个是 `delegate`：desc 791 + 参数 464 |
| | | **实测 `prompt_tokens` = 7,386** |

**7,386 token 是每一步都要重发的底价。** 一趟心跳约 7 次 LLM 调用，
光重发就 **≈52k token**。按现在「三类唤醒 + 睡眠」的节奏一天约 15 轮 →
**≈776k token/天**，也就是说这个项目的成本**几乎全部**是这 7,386 的重复重发。

> ⚠️ 别用"字符数 ÷ 2.4"去估 token —— 实测下来这个粗估法偏高 13%~15%
> （我按它算出 8,382，实测 7,386）。**要报账就发一次真请求读 `usage.prompt_tokens`**，
> 脚本在 `.tmp/measure_fixed.py`，成本约 7k prompt token、回复限 4 token。

### 下一刀：`base_prompt`（**尚未开工**）

`base_prompt` 4,866 字符里最大的一块是 `delegate` 那一节（**1,167 字符 = 24%**），
而同一件事（"3 个以上标的就派子代理"）在 `base_prompt` + `beat_context_template`
里**说了三遍**，`delegate` 这个词单在 `base_prompt` 里就出现 **11 次**
（加上 beat 模板 1 次、工具描述 2 次）。典型的"怕你不懂所以框起来再说一遍"。

**砍一半 ≈ 每次省 1,830 token ≈ 一天省 190k（日成本约 19%）。**

开工前两件事：
1. 读 `HANDOVER.md` 的「八、下一步」—— 那里是完整 brief（现状 / 目标 / 做法 / 陷阱）。
2. **先跑 `bash runtests.sh prompts`。** 这份测试就是为这次重写写的：
   它只钉语义不评文风，把"绝不许丢的东西"（风控边界、三问、成本口径、
   子代理契约、睡眠语义、人格边界）写成了断言。
   写完它当场就抓到一处过时前提 —— 成本纪律那节还写着固定心跳时代的
   "15 分钟里 BTC 大概率只动 0.1%"。

### 换模型 / 调频率之前先看这个

实测（Gemini-3.8-Flash-Thinking 时代的记录，30 个工具，心跳 120 秒）：

| 项目 | 数值 |
|---|---|
| 单轮心跳耗时 | 150–240 秒 |
| 单轮心跳 token | **约 65,000** |
| LLM 调用次数/轮 | 约 7 次 |
| 固定开销 | 系统提示词 ~2k + 工具定义 ~5k，每次调用都重发 |

**量级换算**（这是固定心跳时代的记录，唤醒机制重做之后已经不适用了 ——
现在决定成本的不是"多久醒一次"，而是"多久**有必要**醒一次"，
睡眠期间定时唤醒全部静默，所以实际数字要看第十八节）：

| 心跳间隔 | token/天（旧口径） |
|---|---|
| 120 秒 | ≈ 180 万 |
| 900 秒 | ≈ 25 万 |

> `HEARTBEAT_SECONDS` 这个变量 **2026-09-27 已删干净**。调度器早就不读它，
> 但 `.env` 里留着、`status()` 还在报，看起来像个还能拧的旋钮，其实线路断了。
> 唤醒节奏唯一的判据是 `/data/logs/wake_policy.json`（面板可改），见第十八节。

调成本现在靠这几个旋钮：

- **唤醒策略**（面板右栏，或 `config/wake_policy.json` 种子）—— 影响最大；
  尤其是定时兜底间隔、每小时价格触发上限、睡眠配额
- `MAX_TOOL_RESULT_CHARS` —— 工具输出回灌上限（默认 2000）
- `LLM_MAX_STEPS_PER_BEAT` —— 单轮最多几次「思考-调工具」循环（默认 12）
- `COST_NUDGE_AFTER` —— 运行时成本提醒的口径（按**取数次数**，不是调用总数）

⚠️ **思考型模型的坑**：Gemini Thinking / DeepSeek / o 系的 **reasoning token 也计入
`max_tokens` 预算**。实测回答 19 个字用掉 285 completion token，其中 275 是思考。
所以 `LLM_MAX_TOKENS` 不能设太小，否则答案会被静默截断 —— 默认 16384 是留足余量的值。

## 十一、子代理（省钱的核心机制）

主 Agent 每一轮心跳都要把「系统提示词 + 全部工具定义 + 所有历史消息」重发一遍，
所以它每多看一条数据、每多调一次工具，成本都是**平方级**上涨的。
而它值钱的地方在**判断**，不在于**搬运数据**。

子代理就是这个矛盾的解法：一个更便宜的模型，在**自己独立的上下文里**把脏活干完
（「扫 20 个币找异动」「把 300 根 K 线读成一句结论」），只把一段浓缩结论交回主 Agent。
主上下文完全不膨胀。

```
主 Agent                    子代理（便宜模型）
   │                              │
   ├── delegate(task, want, model)─►│
   │                              ├─ market__get_technical_snapshot × N
   │                              ├─ ...（原始 JSON 全留在子代理上下文里）
   │                              └─ 自己算完，压缩成 600 字结论
   │◄──── 一段紧凑结论 ────────────┘
   │
   └─ 主上下文只增加这几百字
```

**实测**（派一个「扫 4 个标的多周期状态」的任务）：

| | |
|---|---|
| 子代理内部工具调用 | **9 次** |
| 子代理消耗 | 11,398 token（便宜模型），**14 秒** |
| 回传给主 Agent | 约 900 字的结构化结论 |
| 如果主 Agent 自己干 | ~9 次快照的原始 JSON 全部进入上下文，并在后续每步重复计费 |

### ★ 关键经验：让 Agent 用子代理，靠的是运行时数字而不是提示词

**踩过的坑**：最初我把子代理的用法写了整整一节提示词（该派什么、不该派什么、
并行怎么用、写 `task` 的技巧），结果 Agent **一次都没用**。

原因有两个：
1. 它在**清单式地执行**「1看账本 2看盘面 3搜索 4读笔记 5决策 6记录」，
   而"该派给子代理"被写在清单之外的一节里，等于没写。
2. 它**不会预判**"这个子问题要调 3 次工具"——它是一次一次往前走的，
   所以"预判 ≥3 次调用"这种触发条件永远触发不了。

**解法**（两层，都要）：

1. **把 delegate 塞进清单的决策点。** 第 2 步「盘面感知」现在就写明分流：
   1~2 个标的自查、**3 个以上标的多周期就派 delegate**。
2. **运行时提醒。** 一轮心跳里**自己取数**（`market__*` / `exa__*`）超过
   `COST_NUDGE_AFTER`（默认 3）次、且本轮还没用过子代理时，harness 会往
   **那条取数结果的末尾**追加一段：
   > `[成本提示] 本轮你已经自己取了 4 次行情／搜索（market__get_technical_snapshot ×4），`
   > `这些原始返回会在后面每一步里重复计费。关注列表里 SOLUSDT、BNBUSDT 还没看：`
   > `要看就一次派出去。接下来如果还要取数……请一次 delegate 派给子代理。`
   不新增消息、不改角色，零兼容风险。**这一招立竿见影** ——
   加上之后第一轮心跳，Agent 就自己挑了 `deepseek-v4.1-flash`
   （白名单里最强的一个），写了规范的 `want`，还顺手用上了 `tail_lines`。

### ★ 第二次踩坑：口径错了，提醒就会变成噪音

上面那招**只灵了一轮**。后面连续 7 轮心跳，提醒每轮都发，子代理一次都没再被用；
Agent 的思维链里甚至把它误读成「系统在告诉我工具调用配额快满了」，
然后选择「就此收尾」。

翻日志找到了真正的原因 —— **不是 Agent 变懒了，是计数口径错了**：

| 一轮心跳的真实构成（23:10 / 23:13 / 23:18 三轮） | 次数 |
|---|---|
| `fs_read` 读笔记、`fs_list` 列目录、`fs_append` 写日志 | 4~5 |
| `paper__get_events` / `paper__get_risk_limits` / `paper__snapshot_equity` | 2~3 |
| **`market__*` 取数** | **1** |

也就是说，老口径下"已调用 5 次工具"里**只有 1 次是取数**，其余全是每轮必做的琐务 ——
既不该外包、也躲不掉。结果是：**提醒每轮都空响**，而 Agent 两轮就学会了无视它。
更糟的是提醒被贴在了 `fs_append` / `paper__snapshot_equity` 这类结果后面，
看起来毫无来由。

改法（`brain/trader/agent.py`）：

- 计数口径从「工具调用总数」改成**「取数次数」**（`market__*` / `exa__*`），
  阈值默认 3 —— 与提示词里"同类取数到第 3 次就停手"那条纪律对齐。
- 覆盖情况按**返回体里出现了哪些关注标的**判定，所以
  `market__get_market_overview` 这种一把全覆盖的批量工具会被正确识别，
  Agent 不会再收到"你还没看 SOLUSDT"这种假情报。
- 提醒只贴在**引发它的那条取数结果**末尾；本批没有取数调用就往后延，
  留给下一批。
- 文案里点名"还剩哪些标的没看"（状态推导，不是套话），并把事件
  `cost_nudge` 的正文一起写进事件流 —— 否则事后根本无法复盘"它当时到底说了什么"
  （上一版的 `cost_nudge` 事件只有一个数字，这也是前面排查慢了一小时的原因之一）。
- 面板上多了一行实时读数：`并发 0/3 · 上轮取数 1 · 委派 0`，
  一眼就能区分"子代理没被需要"和"子代理该用没用"。

`test_nudge.py` 把这条纪律焊死了：9 次纯琐务调用**不许**出声、
覆盖完成的标的不许再点名、同一轮只提醒一次、已经派过就不再提醒。

**修好之后的真实读数**（重启后第一轮）：

```
last_beat: {"tool_calls": 10, "fetch_calls": 1,
            "fetch_tools": {"market__get_market_overview": 1},
            "symbols_seen": [BTCUSDT, ETHUSDT, SOLUSDT, BNBUSDT],
            "delegates": 0, "nudged": false}
```

10 次调用、1 次取数、4 个标的全覆盖 → **提醒安静了**。
这个数字本身也是结论：Agent 已经学会用一次 `get_market_overview` 覆盖全部关注列表，
所以"delegate 调用长期为 0"并不等于纪律失效，而是它自己找到了更便宜的路。
判断是否该干预，得看**取数次数**，不能看工具调用总数。


### 模型白名单：由人类决定，Agent 只能挑

白名单在 `config/subagent_models.json`，人类维护。每个模型带 `use_for` / `avoid_for`，
**会动态注入到 `delegate` 的工具描述里**，所以 Agent 是"看懂差别后选择"而不是瞎猜。
JSON schema 用 `enum` 锁死候选 —— 它物理上无法指定白名单外的模型，
就算幻觉出一个名字也会被明确拒绝（而不是悄悄换成别的）。

```bash
bash set-subagent.sh --list                  # 查看白名单
bash set-subagent.sh --interim               # 灌入三个实测可用的便宜模型
bash set-subagent.sh --add <id> <base_url> [api_key_env] [max_tokens]
bash set-subagent.sh --remove <id>
bash set-subagent.sh --default deepseek-v4.1-flash
bash set-subagent.sh --off                   # 清空（delegate 不再暴露）
```

**已知在本端点可直接用的便宜模型**（实测支持 tool calling）：
`glm-5.3-fast`（最省）、`qwen3.8-27b`、`deepseek-v4.1-flash`（最强，会主动指出任务前提有问题）

不可用：`Gemini-2.5-Flash(-Lite)`、`Gemini-3-Flash`（无可用通道 503）、
`gemma-4-31b`（已归档）、`gpt-5.6-luna`（无 auth）。

### 密钥怎么放（重要）

**白名单文件里不放密钥，只放密钥所在的环境变量名。**

```json
{ "id": "minimax-m2", "base_url": "https://api.minimax.../v1",
  "api_key_env": "SUBAGENT_API_KEY_MINIMAX" }
```

然后 `.env`（600）里加一行 `SUBAGENT_API_KEY_MINIMAX=sk-xxx`。

这样做的好处：`config/` 可以公开可读，而密钥只在 brain 进程的环境变量里 ——
**Agent 的 `run_shell` 会清空环境变量，所以它拿不到任何 key**。
（如果把密钥明文写进 JSON，Agent 一句 `cat /app/config/*.json` 就偷走了。
代码里对明文 `api_key` 字段会**报错并忽略**。）

密钥回落链：`api_key_env` → `SUBAGENT_API_KEY` → `LLM_API_KEY`（同端点时直接复用主 key）。

### 并发与配额

- `SUBAGENT_MAX_CONCURRENCY=3` —— 同时最多 3 个子代理在跑
- `SUBAGENT_MAX_PER_BEAT=8` —— 单轮心跳最多派 8 次（成本护栏，与并发是两个轴）

为了真并发，harness 把工具调用分成了两批：**只读的并发执行，动账本的严格串行**。

| 并发执行 | 严格串行 |
|---|---|
| `market__*`、`exa__*`、`paper__get_*`、`delegate`、`fs_read`、`fs_list` | `paper__buy`/`sell`/`close_all`/`set_stop_*`、`fs_write`、`fs_append`、`run_shell` |

理由：两个 `buy` 并行会互相踩踏（读到的现金是旧的），而读行情并行没有副作用。

**并发上限是实测过的**，不是纸面承诺。`test_cap.py` 一次发 5 个 `delegate`
（故意超过上限 3），一个 0.1 秒粒度的看门狗盯着 `subagent.active`：

```
配置的并发上限 = 3     配置的单轮上限 = 8
一次发 5 个 delegate 调用（超过并发上限，看会不会排队）

耗时 4.5s   成功 5/5   观测到的最大并发 = 3（配置上限 3）
本轮配额使用 = 5/8     token 总计 22969（glm-5.3-fast）
✓ 并发上限守住了（峰值 3 ≤ 3）
```

即：超出的那 2 个任务在信号量上排队，峰值从不越过上限，配额计数也精确
（5 次而不是 8 次）。跑法见文末"测试脚本"。

### 权限边界（子代理能做什么）

子代理只拿到 **9 个只读行情 + `fs_read` + `fs_list` = 11 个**。它**不能**：
下单、写文件、执行命令、再派子代理（禁止递归）。

代码里还有兜底：即便模型幻觉出一个越权工具名，`_run_tool` 也会拒绝。

### 面板

顶栏 token 计数分开显示主 Agent 与子代理。右栏有**子代理池**卡片：
每个模型的擅长/不擅长、默认标记、并发槽位（`▮▮▯`）、各自的 token 消耗，
标题右侧一行实时读数：`并发 0/3 · 上轮取数 1 · 委派 0` ——
**这一行是用来读病的**：取数为 1、委派为 0 说明"子代理本来就不需要"；
取数 8、委派 0 才是"该用没用"，那时候该去查阈值和提示词。

日志流点「**子代理**」过滤器，能看到每次委派：派给谁、子代理调了哪些工具、
以及它回来的结论。点「**工具调用**」还能看到 `⇉ 并发执行 N 个调用` 的批次。
成本提醒（`cost_nudge`）会把它当时说的**原文**打进日志流 —— 复盘"提醒为什么没用"
时这是唯一的一手材料，上一版只记了一个数字，排查因此慢了很多。


> **怎么判断值不值**：如果 `delegate` 调用长期为 0，就是提示词或阈值需要调；
> 如果子代理 token 占比过高，说明派得太碎（一两次调用能搞定的事不该派）。


## 十二、人格 / 角色扮演

Agent 的性格是**人类的地盘**，放在 `config/persona.md`。文件内容会被注入到系统提示词里，
决定它的说话方式、用词习惯、以及日志里呈现出来的那点"人味"。

### ★ 先读这条：声音卡 vs 人物志

这个文件**只写"怎么说话"，不写"是什么人"。**

原因很实在：`persona.md` 的每一个字都会随「系统提示词 + 25 个工具定义 + 全部历史」
在**每一步**重新发送一遍，按平方级计费。曾经放过一份 6000 字的完整设定，
里面真正影响判断的可能不到 200 字，剩下 5800 字每轮都在烧钱。

更麻烦的是副作用：**角色卡越长，模型越容易滑进"表演模式"**，
输出从"判断"漂移成"看起来像在判断的散文"——叙述欲会挤占计算欲。

所以现在是两个文件，各管各的：

| 文件 | 长度 | 谁读 | 写什么 |
|---|---|---|---|
| `config/persona.md` | ~250 字 | **操盘层**（每轮固定开销） | 说话方式、用词习惯、对什么有本能反应 |
| `config/character.md` | 不限 | **叙事层**（只在写日志时读） | 关系、经历、外貌、脾气、所有细节 |

**`character.md` 永远进不了操盘上下文。** 操盘层看到的只有那 250 字。
完整设定留给第十三节的叙事层——那里它不占固定开销，而且写出来的东西更好看。

### 提示词的三层结构

```
1. base_prompt   身份、约束、心跳动作清单、决策纪律、成本纪律、子代理用法
2. persona       ← config/persona.md 注在这里（只写表达，不写判断）
3. closing       收尾定调 + 关注列表（放最后，靠"近因"强化纪律）
```

**人格刻意放在第 2 层**：位置足够靠后（对语气的影响够强），但最后发言权仍留给纪律层 ——
避免"扮演入戏"压过风控。

### 写声音卡的两个原则

**一、只写表达，不写判断。** 判断已经在 `base_prompt` 里了。写"你说话简短"是风格；
写"你要谨慎"是重复纪律，会让模型收到两个权威，反而更容易忽略数字。

**二、风格可以同向放大纪律，但不能反向抵消。** 比如
「看错时直接写我错了，因为……」「对'这次一定会涨'有生理性厌恶」——
这两条既是性格，又正好是纪律。**这种人格不是负担，是纪律的放大器。**
反过来说，「豪赌的疯子」就必须靠下面那段边界声明去关笼子。

### 边界：角色是皮，纪律是骨

注入人格时，harness 会自动加上这段边界声明：

> 它有一条明确边界：**它不改变你的风控纪律、不改变任何数字、不改变决策逻辑。**
> 如果这段设定里的东西与纪律要求冲突（例如角色设定说"你是个豪赌的疯子"），
> **纪律优先**。角色是皮，纪律是骨。

所以你可以放心写有趣的人格，不用担心它真的去乱赌。**而且就算它真的听了人格的话乱来，
风控是代码 —— 照样拦得住。**

### 用法

```bash
bash set-persona.sh --show              # 看当前人格与状态
bash set-persona.sh --clear             # 清空，回到默认无性格状态
bash set-persona.sh --example A         # 从示例灌一个（A 老练交易员 / B 话痨分析师 / C 极简主义）
bash set-persona.sh --file my.md        # 用本地文件覆盖
bash set-persona.sh                     # 直接从 stdin 粘贴（Ctrl-D 结束）
```

**改完立即生效，不用重启** —— 每次心跳都会重新读这个文件，看不到就退回默认性格。
面板右栏的 token 提示里会显示是否加载了人格。

### 三个内置示例（在 `config/persona.example.md` 里）

| | 风格 |
|---|---|
| **A 老练的交易员** | 简短、干燥、不带情绪。看错时直接写"我错了，原因是……"。对"这次一定会涨"有生理性厌恶。 |
| **B 话痨分析师** | 精力过剩，爱用比喻，会自我推翻。但下单时反而变得谨慎。 |
| **C 极简主义** | 几乎不说话，只写必要几行：账户、关键数字、决定、一行理由。 |

自己写的时候，描述**语气和用词习惯**比描述"世界观"更有效 ——
模型更容易模仿具体的说话方式，而不是抽象的设定。

## 十三、叙事层（把干巴日志重写成"人写的"）

> **2026-09-27：提示词已整体重写。** 起草交给了 `Gemini-3.2-Pro/Antigravity`，
> 过程与结论见本节末尾的「★ 提示词重写」。

前面那套东西跑起来之后，日志是这样的：

```
[23:04:25] thinking  均线纠缠，RSI 50.7，布林带宽 0.46%，量比 0.97……
[23:04:34] tool_call market__get_technical_snapshot {"symbol":"BTCUSDT",...}
[23:05:02] tool_result {"sma20": 84053.2, "sma50": 84052.8, ...}
[23:05:40] beat_summary ### 一、账户与事件流检查 - **当前权益**：10,000.00 USDT…
```

准确、完整、也没人看得下去。

叙事层就是补这一层：**读同一份事件流，用角色的口吻重写一篇**。
但它是**单向的**——这是整个设计里唯一不可动摇的约束。

### 三层结构

```
第 1 层  base_prompt   纪律骨架 ── 不碰。角色不参与风控和任何数字
第 2 层  persona       声音卡   ── config/persona.md，只写"怎么说话"
第 3 层  closing       关注列表 + 收尾定调

        ─────────────────────────────────────────────────────
  侧挂   character.md   完整人物志 ── 只给叙事层，操盘层永远看不到
  出口   叙事层          角色活在这里 ── 一次性的，不污染决策
```

### ★ 单向：为什么它不可能影响操盘

```
操盘上下文 ──► 事件流 ──► 叙事层 ──┬──► 事件流（narrative 事件）
                                    └──► /data/logs/journal.md
```

这个保证**不是靠约定，是靠形状**。叙事层在本项目里只有一个调用点，
它是 `agent.py` 里的一段，全文三行：

```python
result = await self.narrator.narrate(events, self.beats)
if result:
    self.bus.emit("narrative", **result)
```

返回值交给 `bus.emit`，然后就没有然后了 —— `emit` 只写内存缓冲和 JSONL，
代码里**根本没有**把事件 append 回 `messages` 的路径。

想知道有没有泄漏，读那三行就够了。`test_narrator.py` 把这个不变量焊死了：
它断言 `_narrate` 里没有 `messages.append`、没有 `return result`、
整个 agent.py 里除了那句 emit 之外没有任何 narrative 引用。

> 换句话说：**叙事层的输出配多贵的模型、写多长，都不影响任何一笔交易。**

### 什么时候写：两条触发

| | 条件 | 行为 |
|---|---|---|
| **A. 有事** | 成交 / 被风控拒绝 / Operator 留言 / 报错 | **立刻写**，不等计时器 |
| **B. 太久没说了** | 距上次叙事超过 `NARRATOR_MAX_GAP`（默认 6h） | 写一篇回顾 |

**B 不是"兜底"，它本身就是内容。** 震荡行情里 Agent 可以一整天不开仓，
而"为什么不开仓"恰恰是最该记下来的：

> 十二轮心跳，一笔没开。不是克制，是这盘子真没什么好看的。
>
> BTC 在 83,600 到 84,350 之间磨了十二轮，SOL 顶着 122.94 上不去也下不来。
> 15 分钟振幅 0.08%，而过一次手是 0.30% 左右的手续费加滑点。我得先赢四次
> 才能回到起点，这种比例的买卖不叫交易，叫交学费。
>
> 我想等的条件一直很具体：BTC 带量站上 84,350，或者干脆丢掉 83,600，
> 量比过 1.5 再谈……这些一个都没出现。
>
> 所以入场三问，我一个也答不上来。答不上来就不动。空仓也是一种仓位，
> 只是押在了"不参与"这一边。

**素材范围是"自上次叙事以来的全部事件"，不是"本轮"。** 所以定时触发时
它写出来的是一段回顾，而不是流水账。

#### ★ 踩过的坑：`events` 模式几乎不响

最初的触发条件是「有事才写」，还顺手把 `cost_nudge`（系统的成本提醒）
也算进了"有事"。跑了 35 轮之后统计：

```
按 _NOTABLE 判定会触发叙事的心跳:  1 / 35  = 3%

触发源拆解:
  cost_nudge   11 次
  error         1 次
```

两个结论：

1. **`events` 模式等于不写** —— 35 轮只响 1 次，安静的时候面板一片空白。
2. **唯一在响的触发源是 `cost_nudge`** —— 效果变成"系统每唠叨一次就写一篇日志"，
   和初衷正好相反。那个提醒本身在第十一节里就记着"会被无视"，拿它当触发源是错的。

所以现在的口径是：**去掉 `cost_nudge` 和 `skipped`，改成"有事立刻就写 + 憋久了也写"。**

### 素材怎么压：预算分配

6 小时的窗口 = 24 轮心跳，每轮正文中位 862 字 —— 直接拼起来是 **2 万字**，
撞死在 `MAX_DIGEST_CHARS=9000` 上，而且撞死的方式是"尾部被砍掉"，
砍掉的恰恰是最近的、最该看的内容。

所以按预算分配，**三条规则**：

```
1. 事件（成交 / 被拒 / 留言 / 报错）是稀疏的 → 完整保留，不参与分配
2. 最近一轮给足（它是最新状态）
3. 剩下的预算分给更早的轮次，用计数器硬拦

   ★ 不能靠"每轮夹在 [100, 900]"这种软约束 —— 96 轮时 96×100 = 9600 > 9000，
     溢出后截断砍的还是尾部。
```

**还有两个拿真实日志量出来的判断：**

**取最后一段，不取最长的一段。** 操盘 Agent 的输出是
「账户模板 → 盘面罗列 → 决策 → 下轮监控」的格式化报告。最长的那段就是整篇报告，
八成是数字；**最后一段才是收尾结论** —— 决定了什么、为什么。

**截断时向尾部压。** 报告的**开头**是每轮一模一样的「账户与持仓核对 / 总权益 10000」，
**结尾**才是「本轮决策 + 下轮监控」。所以：

```
最近一轮   留 1/4 头 + 3/4 尾（它是当前状态，要完整）
更早的轮次 只留尾部（只要它当时的结论和在看什么）
```

效果（同一份线上数据，12 轮窗口）：

| | 素材 | 输入 token | 产出 |
|---|---|---|---|
| 优化前（拼接 + 取最长） | 7937 字 | 6627 | 490 字 |
| 优化后（分配 + 取结论 + 剥八股） | **2375 字** | **3322** | 443 字 |

顺带还做了一件事：**剥掉模板八股**（markdown 表格行、每轮重复的账户状态行、
结尾的"已更新笔记/权益采样已打点"），实测能再省 16%。
以及**同一条事件重复出现时压成「×N」**—— 调度器异常每 30 秒重试一次，
一个窗口里塞进 7 条一模一样的报错，把预算吃了还让素材看起来像出了 7 次不同的事故。

### 手账为什么落在 `logs` 而不是 `workspace`

叙事层写一篇，就往 `/data/logs/journal.md` 追加一条。这个落点是刻意的：

**工作区是 Agent 自己能 `fs_read` 到的地方。** 手账放进去，等于把叙事
从后门喂回了操盘上下文 —— 那单向保证就白做了。而日志目录本来就已经以 rw
挂载给大脑（事件流就写在那儿），不需要额外开任何挂载。

> ⚠️ 上面那句「单向保证」在 2026-09-27 之前**只对 `fs_*` 成立** ——
> `run_shell` 当时没有 chroot，`cat /data/logs/journal.md` 就能读回来。
> 现在 Landlock 把它一起管住了（第六节）。**约定和物理保证是两回事**，
> 这里踩过一次，别再踩第二次。

手账还有个用途：**叙事节奏靠它跨重启保持**。`_last_at` 从手账最后一条标题行
（`## beat #12 · 2026-09-27 06:30`）读回来。不这么做的话，每次重建容器
计时器就归零，于是"刚写完就立刻又写一篇"—— 实测重建一次就多一条重复的 `beat #1`。

### 关于长度

`NARRATOR_MAX_CHARS` 是**整篇**的上限（聚合窗口跨多轮时也是这个数），不是每轮。

实测发现"硬上限"这种措辞收效甚微：写 400 字上限，它交了 456 字；改成"这是硬上限"
之后，下一轮交了 607 字。根子在**输入太肥** —— 素材直接继承操盘层自己的话，
而它那轮说了几百字。所以真正的解法是压素材（见上一节），不是加措辞。

现在的默认是 600 字。实际产出稳定在 440~550 字之间。

### 模型怎么选：**别用 DeepSeek 干写字的活儿**

> ## ⛔ 硬规矩：`deepseek-v4.1-flash` 不许用来写任何文字类产出
>
> **文笔很差，文科很差。写总结、写角色日记、写叙事、写复盘叙述 —— 一概不许交给它。**
> 这是 Operator 定下的规矩，不是口味问题。同一份素材、同一个提示词摆在一起对比过，
> 它写出来的东西是**合规报告**那个味道：短句、破折号、编号感、
> 什么都要"首先其次最后"，读起来像给上级交的周报。叙事层那次退稿的理由就是
> "有一股死人味儿"，那味儿就是它带来的。
>
> **它可以干的活**：结构化提取、数值汇总、把长数据序列读成一句结论、
> 判断形态成不成立、指出任务前提本身有问题 —— 这些是它的强项（见第十一节）。
> 换句话说：**当工具用没问题，当笔用不行。**
>
> 这条同样适用于 whitelist 里那份 `use_for` / `avoid_for` —— 那边的描述要跟着改。

**写字的活儿交给思考型的强模型。** 现在叙事层用的是主模型
`Gemini-3.8-Flash-Thinking/Antigravity`。换模型时有个**必须一起改**的地方：

```
NARRATOR_MODEL=Gemini-3.8-Flash-Thinking/Antigravity
NARRATOR_MAX_TOKENS=8192        ← 不改成这么大，日志会被拦腰截断
```

**为什么这个数必须跟着改**（实测，不是推断）：思考型模型的
**reasoning token 也算进 `max_tokens`**。拿线上真实素材跑了一次，`max_tokens=2000` 时：

```
finish_reason : length          ← 截断了
completion    : 1996
  └ reasoning : 1922            ← 思考一个人吃掉 96%
正文          : 94 字           ← 然后就没了
```

对照：同一个 `max_tokens=2000` 给非思考模型，`finish=stop`、正文 561 字、正常收尾。

**截断的后果比"少几句"严重得多。** `journal.md` 是 append-only 手账，写进去就不会重写；
而它还是跨重启恢复叙事节奏的唯一依据（`_restore_last_at` 读最后一条标题行）。
一篇被腰斩的日志会**一辈子待在账本里**，而且下次重启后节奏照常从它那里接着算。

所以：**换模型时必须一起看 `NARRATOR_MAX_TOKENS`。** 换成思考型就往上抬
（8192 是留过余量的值：思考 ~2k + 600 字正文 ~1.1k，再宽一倍）；
换回普通模型可以降回 2000 省钱。

### 开关与配置

默认**关闭**。打开：

```bash
# .env
NARRATOR_ENABLED=true
NARRATOR_MAX_GAP=21600          # 6 小时；设 0 = 每轮都写（约 96 篇/天，很费）
NARRATOR_BASE_URL=...           # 不给就回落主 LLM
NARRATOR_MODEL=Gemini-3.8-Flash-Thinking/Antigravity
NARRATOR_MAX_TOKENS=8192        # ★ 思考型模型必须给够，见上一节
NARRATOR_CHARACTER_FILE=/app/config/character.md
```

温度单独配（默认 0.85，比操盘的 0.3 高得多 —— 写东西和做判断需要的温度不一样）。

**别为了省几毛钱把写字的活儿外包给廉价模型。** 这一条的账很好算：
叙事层 6 小时一篇、一天 4 篇，用主模型一个月也就多几毛钱；
而它是**唯一给人类看的东西** —— 操盘层亏赚都在账本里，你会读的其实是这些日志。
省在这里，等于把整个项目里唯一有阅读价值的部分换掉了。

### 成本量级

| 配置 | 篇数/天 | token/天（约） |
|---|---|---|
| `MAX_GAP=21600`（6h，默认） | 4 + 事件触发 | ~15k |
| `MAX_GAP=3600`（1h） | 24 | ~70k |
| `MAX_GAP=0`（每轮） | 96 | ~280k |

对照一下：操盘层自己是 900s 心跳 ≈ **250k token/天**。
所以「每轮都写」约等于**再养一个操盘 Agent**。「6 小时」是它的十六分之一。

### 失败姿态

叙事是装饰，不是功能。任何异常都被就地吞掉：模型不通、超时、返回垃圾，
都只是这一轮没有日志，**绝不允许影响心跳本身**。

### 面板

- 叙事卡片是日志流里最醒目的一层（左侧竖线 + 渐变底 + 更大的行高）
- 过滤器里点「**日志**」只看这一层
- 顶栏 token 胶囊的 tooltip 里显示叙事层状态（模型、模式、上次时间、人物志字数）
- 它会渲染一小部分 markdown（加粗 / 分隔线 / 引用 / 行内代码），因为
  `character.md` 里写了他用这些格式

### 日志里那些 `$` 和 `\` 是什么（LaTeX）

**先说一个我犯过的错，而且我一开始的归因是错的。**

原始设定里有一句：

> 数学公式必须使用LaTeX格式。**对 Operator 问的数学问题**，你会给出严谨的证明……

它明确限定了场景 —— **回答数学问题时**。但我写成"涉及数字、指标、盈亏时必须用 LaTeX"，
把要求扩大化了。结果 Agent 开始写 `$83{,}600$`、`$0.30\%$`、`$1.5$` ——
一个交易日志里的百分比，写 `0.30%` 比 `$0.30\%$` 干净得多。

**这不是渲染问题，是提示词问题。** 所以两边都得修：

| 端 | 做什么 |
|---|---|
| 提示词 | `character.md` 和叙事层的 system prompt 都写明：数字和百分比用普通写法，只有真正的数学推导才上 LaTeX |
| 面板 | 兜底渲染残留的 LaTeX（下节） |

#### ★ 但"叙事层那 33 个 `$` 是哪来的"，我第一次判断错了

当时我认定是**旧提示词自己给了三个可照抄的坏样例**（`$0.30\%$`、`$83{,}600$`、
`$\text{ATR}_{14}$` 就写在负面指令后面），所以产出才满屏 `$`。听起来很有说服力。

事后核账发现：

| | 含 `$` 的比例 |
|---|---|
| 手账（叙事层产出） | **33 处** |
| 操盘层自己的输出（素材来源） | **10% 的文本** |

**主要的 LaTeX 是叙事模型自己生成的，不是从素材抄的。** 反面样例顶多是帮凶。
我把一个听起来漂亮的归因当成了结论，记在这里免得下次重犯 ——
**"提示词里有坏例子"和"模型自己爱写"是两回事，得看数据才能分开。**

改完的效果：操盘层的 29 轮输出里只剩 1 轮带 LaTeX。


### 面板的轻量 LaTeX 渲染

**没有引 KaTeX。** 那是 371KB，而日志里需要处理的只有 `\text{}`、上下标、`\%`
和几个比较符号。为这个引一个数学排版引擎不划算 —— 等真的需要渲染 Agent 的
数学推导时再说。

实现是 `index.html` 里的 `texLite()` + `texBody()`，约 50 行。

#### ★ 唯一的坑：`$` 也是货币符号

日志里同时存在两种东西：

```
真 LaTeX：$0.30\%$、$\text{ATR}_{14}$、$\ge 2:1$、$83{,}600$
美元符号：$2,690（未闭合）、$300-$400（区间）、$10,000.00 USDT
```

**粗暴地去掉所有 `$` 会把美元符号吃掉。** 所以只处理**能认出是 LaTeX 的**：

```js
// 认得出的特征
const TEX_HINT = /\\[A-Za-z]|\\%|\^|_\{|_[\dA-Za-z]|\{,\}|&#123;,&#125;|^[0-9][0-9,.]*$/;
//                ↑ 反斜杠命令  ↑ \%  ↑ 上下标      ↑ 千分位      ↑ 纯数字（83,600 / 74）
```

`^[0-9][0-9,.]*$` 这个"纯数字"分支刻意**不含 `:` 和 `-` 和空格**，
这样 `$0.8:1$` 和 `$300-$400` 不会误判。再加一条保护：
**以 `-` 结尾的一律不渲染**（几乎肯定是美元区间）。

**认不出来的原样保留 —— 宁可不渲染，也不吃掉货币符号。**

#### 安全性

`texBody()` 的输入已经过 `esc()`，所以不存在 HTML 注入路径：

```
输入  $\text{<img src=x onerror=alert(1)>}$
输出  <span class="tex">&lt;img src=x onerror=alert(1)&gt;</span>
```

它内部先把 `&lt;` / `&gt;` 换成占位符处理，最后才还原 —— 这样数学内容里
即使有尖括号也不会被当成标签。

#### 怎么验证改坏了没有

`texLite` 是纯函数，改完一定要拿这几类真实样本过一遍（19 项断言，覆盖
LaTeX 渲染 / 货币保留 / 注入转义 / markdown 共存）：

```bash
# 从 index.html 里抽出 esc() 到 mdLite() 之间那段，喂给任意 JS 引擎跑
python3 - <<'EOF'
import re, pathlib
js = re.search(r"<script>(.*)</script>",
               pathlib.Path("brain/static/index.html").read_text(), re.S).group(1)
start = js.index("const esc ="); end = js.index("let FILTER =")
pathlib.Path("/tmp/frag.js").write_text(js[start:end])
EOF
```

`_digest` 是纯函数，可以直接拿线上事件日志离线跑：

```bash

ssh root@YOUR_SERVER_IP 'cd /opt/ai-trader && python3 /tmp/cmp.py 12'
```

排「素材为什么这么长」「某类事件为什么没进去」这类问题时，
这是唯一省事的办法 —— 不用真的写一篇、花一次 token。

### ★ 提示词重写（2026-09-27）

#### 问题是怎么发现的

线上 4 篇真实产出摆出来，毛病很集中：

1. **`$` 泛滥**：`$0.08\%$`、`$83{,}600$`、`$\text{ATR}$`、`$0.8:1$` 满屏
2. **数字像在口述盘面表**，不是写判断
3. **每篇都以杂务流水收尾**：「记了权益采样点，日志也写进 `notes/xxx.md` 了」
   —— 4 篇里 3 篇这个句式
4. **骨架完全一致**：开场一句 → 逐标的罗列 → `***` → 所以不动 → 下轮看什么
5. **人称在"我在写"和"他在做"之间摇摆** —— 提示词通篇用「他」称呼写作者，
   却同时要求「第一人称」

#### 怎么改的

把现状（旧提示词全文 + 人物志 + 4 篇真实产出）打包，交给
`Gemini-3.2-Pro/Antigravity` 起草。它给的稿子采纳了三条主要改动：

| 改动 | 效果（同一份线上素材 A/B 实测） |
|---|---|
| **禁止汇报系统杂务** | 结尾那堆"打了权益点、写进 notes"全没了 |
| **打破模板**（禁止固定句式开头） | 开头从"扫完四个标的"变成能从一个细节切进去 |
| **删掉所有 LaTeX 反面样例** | `$` 从 33 处降到 0 |

它原稿里还有一条「**全文具体数字不超过 4 个**」，实测把数字密度从 17 压到 2，
**但被退掉了** —— 两个理由：一是没必要限制，二是模型规避上限时会改用中文数字
（产出里出现了"零点五到一点一"），量比这种要精度的信息写成中文数字反而更难读。

A/B 对照（同一份线上素材、同一模型、各写一篇）：

```text
指标            旧版      新版
字数             450       459
$ 符号数           0         0     ← 素材本身干净，这轮没触发
数字串个数         17         2
非空行数           9         7
```

新版产出：

> 我盯着 SOL 看了三轮了。它离那道 122.94 的阻力永远差那么一口气，
> 量比摇摆在 0.5 到 1.1 之间，从来没冲上去过。
> **就像有人站在跳板边上，来回晃，就是不跳。** 这种结构最难受 ——
> 你既不能提前埋伏，因为没确认；也不能追，因为空间不够。
>
> 空仓也是一种态度，现金本身就是我的仓位。

#### ★ 这次最大的收获，比任何一条规则都值钱

**提示词自己的语感会渗进产出里。**

我先交过一版，被退了，理由是「**有一股死人味儿**」。回头看这个判断是对的：
我那版把要求写成了 9 条编号的合规清单，短句、破折号、命令式；
Gemini 那版是在**跟模型说话** ——

> 不要用罗列一堆死水数据来凑字数，而是写出你的**思考过程**：
> 你觉得盘面无聊吗？你在等什么条件？为什么现在的条件不够好？

同一套约束，后者更像人话，模型也就更容易把人话写出来。
**"把要求列清楚"和"让模型把话说人"是两件事，写提示词时要盯着后者。**

## 十四、人工干预

面板底部有输入框：发一条消息，它会作为**下一轮心跳的最高优先级指令**被注入
（`## 人类留言` 那个上下文块）。适合纠正跑偏的方向，例如「别碰小市值币」
或「把 BTC 仓位降下来」。

> ⚠️ **留言本身不触发一轮心跳**（2026-09-27 定的语义，面板上那句话跟着改了）。
> 原因是 `decide()` 在睡眠中只认**登记过的**唤醒请求（`request_wake`），
> 而留言走的是另一条路。所以：
>
> - 它**睡着的**时候留言——叫不醒它，留言会一直挂着，直到它自然醒（单次睡眠上限）
>   或被别的触发叫醒。**要它现在读，点「立即唤醒」。**
> - 它**清醒的**时候留言——也只是置了一下唤醒信号；没到兜底间隔、也没有价格触发的话，
>   照样要等到下一轮真的跑起来才读得到。
>
> 这件事**表面上完全看不出来**（事件流里那行 `human_instruction` 确实在，
> 看着就像送到了），所以它被写进了面板的 placeholder：
> `instrHint()` 会按睡眠状态说不同的实话。原来的文案承诺「发送后将立即唤醒」，
> 两半都是假的 —— 2026-09-27 部署时踩到才发现。
>
> 想让留言也能穿透睡眠，就在 `web.py` 的 `instruct()` 里加一句
> `runtime.wake.request_wake("human_manual", ...)`。**没加是刻意的**：
> 睡眠配额是个成本闸门，而「立即唤醒」按钮已经给了人类那条越权通道。

注意：这**只影响判断，不影响风控**。风控是代码，Agent 听不听话都拦得住。

面板顶部按钮：
- **暂停 / 恢复** —— 暂停后不再自动唤醒（当前正在进行的一轮会跑完）
- **立即唤醒** —— 不等倒计时，马上开始新一轮。**这条能穿透睡眠**
  （走 `request_wake("human_manual")`，人有权把人拽起来）

## 十五、Agent 不能改的东西（设计如此）

| 它想做的事 | 为什么做不到 |
|---|---|
| 改自己的风控参数 | 风控写死在 `mcp-paper` 代码里，且 `data/db` 没挂进大脑容器 |
| **改自己的睡眠配额** | **同上 —— 睡眠账本和风控在同一个 SQLite 里** |
| 改自己的性格 | `config/` 是只读挂载，属主是宿主 root，Agent 的 shell（UID 10001）写不进去 |
| **改人类设的唤醒阈值** | 人类的策略在 `config/`（只读）和 `/data/logs/`（它的 `fs_*` 够不到）。<br>✅ **2026-09-27 起它连读都读不到了** —— `run_shell` 挂着 Landlock，`/data/logs` 不在白名单里 |
| 偷偷加一个子代理模型 | 白名单是只读的人类文件；schema 用 `enum` 锁死，运行时还有二次校验 |
| 读到任何 API key | ① 子进程环境变量白名单（挡住 `env`）② brain 进程 non-dumpable + Landlock 拒 `/proc`（挡住 `cat /proc/1/environ`）。见第六节 |
| 读到纸面账本 | `data/db` 根本没挂进大脑容器 |
| 把数据写到工作区之外 | `fs_*` 做 realpath 校验；容器根文件系统只读 |
| 提权 | `cap_drop: ALL` + `no-new-privileges` |
| 逃到宿主机 | 非特权容器、无 docker socket、无宿主挂载 |

> **它能改的**：自己那份唤醒策略（工作区 `wake_policy.json`）——
> 但**只能把兜底间隔改得更短**，人类的值是上界。这个钳位是刻意的，
> 否则它可以给自己放假到明天，"最长沉默"的承诺就作废了。


**唯一的"自由区"是工作区**：Agent 可以在 `/data/workspace` 里自由读写、用 `run_shell`
跑 python 做自建计算。这是刻意留的 —— 它需要纸笔。工作区里没有凭证、没有账本、
没有任何能影响风控的东西。

## 十六、测试脚本怎么跑

大脑的代码是**构建时烤进镜像**的，所以测试脚本不能随手 `docker exec` 进容器跑 ——
镜像里 `/app/trader` 是旧版本，测试会"通过"，但其实考的是改动前的代码。
两个坑都写进 `runtests.sh` 里了（源码要先拷到别处绕开 `sys.path[0]`；
`/opt/ai-trader` 是 700，非 root 的容器用户挂不进去），所以直接：

```bash
bash runtests.sh nudge     # 运行时成本提醒的触发口径 —— 纯逻辑，不联网，不花钱
bash runtests.sh wake      # 唤醒兜底 / 睡眠配额 / 各类钳位 —— 纯逻辑，不花钱
bash runtests.sh hub       # MCP 多块返回值装配 —— 纯逻辑，不花钱
bash runtests.sh sandbox   # run_shell 的 Landlock 白名单 —— 纯逻辑，真挂规则
bash runtests.sh prompts   # 操盘提示词的不变量 —— 纯逻辑，不花钱
bash runtests.sh frontend  # 面板静态检查 + [10] 真 JS 引擎跑一遍（装了 quickjs 才跑那节）
bash runtests.sh web       # /api/market 愿不愿意被慢取数挡住 —— 打 ASGI，不联网
bash runtests.sh public    # 公开只读档：匿名能碰到什么 —— 打 ASGI + 解析 nginx，不联网
bash runtests.sh cap       # 并发上限 —— 要连容器，真发 5 个 delegate，花一点点 token
bash runtests.sh live      # 沙箱的**部署后**验收：打容器里正在跑的那份代码
bash runtests.sh paper     # 睡眠账本的**部署后**验收：一次性 DB 上打真代码
bash runtests.sh all
```

> "沙箱那一段根本没跑"在输出上必须看得出来是两回事。

### `test_sandbox.py` 是怎么来的（两个把约定当保证的真洞）

`run_shell` 原来只设了 `cwd`。实测（线上容器，uid 10001）：

```
$ cat /data/logs/journal.md          → 读得到（叙事层的单向性，在这条路上是漏的）
$ echo x >> /data/logs/zzz           → 写得进
$ cat /proc/1/environ | grep KEY     → 读得到，而且是**明文**
```

第三条是动手时才发现的那个：`env={...}` 清空的是**子进程要拿到的那份**，
brain 自己的初始环境块还在内核里，同 uid 可读。
文档里"密钥只在 brain 进程环境里"这句话，当时**是假的**。

修的过程里还踩了两个只有实测才看得见的坑，都写进测试里了：

1. **`landlock_add_rule` 少传一个参数。** 它要（规则集 fd、规则类型、属性指针、flags），
   少传那个 0，`syscall()` 会把寄存器里的垃圾当 flags，报出来是 `EINVAL` ——
   看起来像"规则不合法"，其实是调用姿势错了。当时的第一反应是去查权限位，
   查错方向了。现在的做法是**降级但不静默**：挂不上就在工具返回值里留一行警告，
   否则整层沙箱会安安静静地等于没有。
2. **wrapper 继承了父进程的环境变量。** 通过 `LocalTools` 走时是干净的
   （调用方传了 env），但直接 `python3 sandbox.py ...` 起 wrapper 时，
   环境里原样躺着 `LLM_API_KEY`。所以"清环境"这件事现在有两个来源：
   `child_env()` 是唯一的事实来源，wrapper 自己 exec 前再换一次。
   测试里那条回归用例就是照这个写的：父进程故意带着一把 CANARY 起 wrapper，
   断言它漏不下去。

### `test_frontend.py` 是怎么来的（一次真事故）

2026-09-27，`index.html` 里 `esc(` 少了一个右括号：

```js
$("#tree").innerHTML = `<div data-path="${esc(j.path? ... replace(/\/$/,""):""}">...
                                                            ↑ 这里少一个 )
```

整段 `<script>` 因此解析失败，浏览器直接放弃它，于是三行初始化
（`tick()` / `loadHistory()` / `connect()`）**一句都没跑**。
用户看到的是：**状态永远停在"连接中"、日志永远空白**。

而后端一切正常（`/api/state`、`/api/events`、SSE 直连和过 nginx 都是 200），
所以从日志和数据那侧完全找不到问题。**排查绕了很久。**

一个丢掉的括号能让整页静默死掉，而症状看起来像后端故障 —— 当时没有任何检查守这条。
现在守了，而且它带**自校验**：测试里塞了一段同样缺括号的 JS，
确认扫描器真的抓得到、且不误报。否则检查器自己坏了也没人知道。

> 扫描器是手写的（跳过字符串/注释/正则/模板字符串，`${}` 里的表达式递归处理），
> 目的是**不引任何依赖** —— tree-sitter 能做得更好，但那要装东西，
> 而这一类的错用两百行纯 Python 就够抓了。少一个依赖多一分可移植性。

### `test_hub.py` 是怎么来的（一个会静默吞数据的坑）

**FastMCP 会把它返回的 list 拆成「一个元素一个 text block」。**
返回 `[{"symbol":"BTC"},{"symbol":"ETH"}]`，拿到的不是一个 JSON 数组，
而是两个 block，各自是一段 pretty-print 的对象。

而 hub 原来是把它们用 `\n` 拼起来的，于是得到：

```
{
  "symbol": "BTCUSDT",
  "price": 84000
}
{
  "symbol": "ETHUSDT",
  ...
```

这**不是合法 JSON**，下游每一处 `json.loads` 都会失败。
更阴的是失败方式：`_safe_call` 解析失败会**安静降级成 `[]`** ——
于是"真的没有数据"和"解析失败"在调用方看起来完全一样，
**整类工具的返回值被静默吞掉，日志里连一行报错都没有。**

这个坑是在接价格监控时才暴露的：`market__get_prices` 之前从没被调过
（Agent 一直用一次性全覆盖的 `get_market_overview`），所以它坏了很久也没人发现。
**一个"没人用"的工具，坏掉是无声的。**

### 为什么会有 `test_lint.py`

这个项目没有 CI，代码是构建时烤进镜像的。一个拼错的变量名**不会被 import 抓到**
（Python 只在真正执行到那一行时才报错），于是它会安安静静进镜像，
然后在**某一轮心跳里**才炸 —— 表现为调度器每 30 秒重试、每次都失败、
日志刷满 traceback，而面板上只显示"有错误"。

真实案例（这个测试就是为它写的）：

```python
# 应该写进 __init__（bus 是那里的参数）
self._last_narrated_id = bus.seq
# 结果被写进了 _beat（那里没有 bus）
```

`py_compile` 通过、`import` 通过、`test_narrator.py` 通过 —— 直到线上跑第一轮心跳
才报 `NameError: name 'bus' is not defined`。

`test_lint.py` 用 AST 把每个名字的读取和绑定对账，这类错它必抓。
它不是 pyflakes，不做流分析，会漏掉一些真问题 —— 但上面这类它一定抓得到。
（它自己也被自己抓到过一次：`bind_target` 漏了检查 `ctx`，
于是 read 位置的名字也被当成"已定义"，整个检查器变成摆设。）

### 测试对象的区别

`nudge` / `narrator` / `lint` 与 `cap` 考的对象**故意不一样**：

| | 考的代码 | 为什么 |
|---|---|---|
| `test_nudge.py` | 工作区里的**当前源码** | 纯逻辑，改完立刻验，不用为了测一行判断去重建镜像 |
| `test_narrator.py` | 工作区里的**当前源码** | 同上。守的是"叙事永不回灌操盘上下文"这条命门 |
| `test_lint.py` | 工作区里的**当前源码** | 纯静态。守的是"用了但没定义的变量"，见本节末尾 |
| `test_cap.py` | 镜像里**已部署的代码** | 并发是运行时行为，必须验"线上真正在跑的那份" |

改完代码怎么上线：`bash push.sh <文件...>` 推上去，然后
`ssh root@YOUR_SERVER_IP 'cd /opt/ai-trader && docker compose up -d --build brain'`。
**只推不重建等于没改** —— 大脑的代码是构建时烤进镜像的（这个坑也是踩出来的），
所以 `test_cap.py` 才特意去考镜像里那份。

### 第 11–15 轮：提醒变成噪音，以及为什么会这样

上一节的"立竿见影"**只维持了一轮**。此后连续 7 轮心跳：提醒每轮都发，
子代理 0 次，Agent 的思维链里还把它读成了"系统在告诉我工具调用配额快满了"。

统计每轮心跳的真实构成后，原因一目了然：

```
beat#N  tool_calls  fetch_calls   构成
        10          1            fs_list/fs_read ×5 + fs_append + paper__snapshot_equity
                                  + paper__get_events + paper__get_risk_limits + market__get_market_overview
```

**"已调用 5 次工具"里的取数只有 1 次**，其余全是躲不掉的琐务。老口径（总数 ≥5）
等于每轮空响 —— 一个每轮都响、且响在无关结果后面的警报，两轮就会被无视。
这不是 Agent 不听话，是信号设计错了。

改完之后（口径 = `market__*` / `exa__*` 的取数次数，默认阈值 3）：

```
last_beat: {"tool_calls": 10, "fetch_calls": 1,
            "fetch_tools": {"market__get_market_overview": 1},
            "symbols_seen": [BTCUSDT, ETHUSDT, SOLUSDT, BNBUSDT],
            "delegates": 0, "nudged": false}
```

10 次调用、1 次取数、4 个标的全覆盖、**提醒不发** —— 这才是正确姿势：
它没在浪费上下文，就不该有人唠叨它。

顺带得到一个反直觉的结论：**"delegate 长期为 0"不一定是纪律失效**。
这个 Agent 已经学会用一次 `market__get_market_overview` 覆盖整个关注列表，
那一刻它比 delegate 更省。要不要干预，得看**取数次数**这个数字，
面板右栏那行 `并发 0/3 · 上轮取数 1 · 委派 0` 就是给这个判断准备的。

### 并发上限（实测，非纸面）

`test_cap.py`：一次发 5 个 `delegate`（上限 3），0.1s 粒度看门狗盯 `subagent.active`。

## 十八、唤醒与睡眠（2026-09-27 重做）

原来只有一种唤醒：固定心跳，每 900 秒一次。**死水行情里那是纯空转** ——
15 分钟醒一次、看一圈发现什么都没发生、写篇笔记、回去睡，一天 96 轮。
而 `README` 自己早就算过：心跳 900s ≈ 每天 25 万 token。

所以改成三类唤醒 + 睡眠。**这一节是这次改动最该读的部分。**

### 三类唤醒

| 触发源 | 谁设的 | 落在哪 |
|---|---|---|
| `schedule` | 定时兜底 | 人类设上界，Agent 只能往短里改 |
| `price_human` | 人类 | 面板 / `config/wake_policy.json`（种子） |
| `price_agent` | Agent 自己 | 工作区 `wake_policy.json` |

### ★ 兜底的语义是「最长沉默」，不是固定节拍

这是设计里最容易被误解的一点。写成一句话：

> **距上一次*任何类型*的唤醒超过 interval 秒，就必定醒一次。**

不是"每 interval 秒醒一次"。看上图更容易懂：

```
T+0    定时唤醒
T+32   自唤醒       ← 距上次唤醒只有 32 分钟
T+60   本该兜底     ← 但距上次唤醒才 28 分钟 → 跳过
T+92   兜底生效     ← 距 T+32 满 60 分钟
```

"拿兜底当保险，但别的唤醒发生了就不需要保险" —— 这个语义**恰好就是**
「保证最长沉默不超过 interval」。而且它天然处理了"连着三次自唤醒"
"三类混合发生"这些情况，不需要额外状态。

**另一种写法**（显式维护"窗口内是否发生过别的唤醒"）要多存一份状态，
还容易在"自唤醒正好卡在边界"上出错。这里选了自然后者。

> 这条语义有个副作用要知道：**它不会每 N 分钟给你一次"例行检查"。**
> 如果人类阈值很敏感（比如 ±1%），那兜底几乎永远轮不到生效，
> 实际唤醒频率由价格触发决定。想知道到底是谁在唤醒它，看面板的触发源统计。

### 价格触发怎么算

**参考价 = 上一次心跳结束时各币的价格快照**，每轮重置。现价相对参考价越界就触发。

为什么用这个口径：

- 不需要维护滚动窗口
- **触发后自动重置**，所以同一价位不会连着响，也不需要去重逻辑
- 它问的问题正好是"自上回你看盘以来，有没有发生值得你醒一次的事"

> ⚠️ **但参考价只在"心跳结束"时写入，所以进程刚起来时它是空的** ——
> 而 `Rule.hit` 里那句 `if self.pct and ref:` 会**安静地**跳过所有 pct 规则。
> 于是就有一个很难发现的组合：
>
> ```
> 重启时它正好在睡  →  没有心跳，refs 一直是空的
>                  →  人类的 ±1% 和它自己押的百分比阈值**全部形同虚设**
> ```
>
> 这个组合是 2026-09-27 部署后才看出来的（面板上 `refs` 显示 `{}`，而 `sleep` 是 `true`）。
> 现在的做法：价格监控**第一次取到价就把当前价当基准**，语义是"从进程启动那一刻起算"，
> 并发一条 `wake_refs_seeded` 事件（面板上看得见）。这一轮仍然照常走一遍规则判定 ——
> `above` / `below` 是绝对价格线，该不该触发跟基准无关。

一批里多个币同时越界时，**算一次触发**，命中的全列进 `reason`：

> 原来看见第一条就 `return`，注释写的是"剩下的下一轮再说"。其实**下一轮轮不到** ——
> 第一次登记就把冷却推到 15 分钟后，第二次直接 False。那句话的实效等于"剩下的被丢掉"。
> 现在配额还是只走一次，但醒过来的那一轮能看到全景。

规则有两种形式（可以混用）：

```json
"thresholds": {
  "BTCUSDT": { "pct": 1.0 },              // 相对上次看盘价波动 ±1%（涨跌都算）
  "SOLUSDT": { "above": 130, "below": 115 } // 价格线：站上 130 或跌破 115 就叫醒
}
```

`default_pct` 兜住"没单独配的币"，但**只在 `WATCHLIST` 里生效** ——
免得它去监控一堆没人看的对。

### 监控在哪跑、花不花钱

brain 里一个后台 asyncio 任务 (`PriceMonitor`)，每 30 秒通过**内网 HTTP**
调 `market__get_prices` 批量取价。

**它不花任何 token** —— 不经过 LLM。所以 30 秒一次也不心疼。

三个护栏（缺一个都会变成烧钱）：

| 参数 | 默认 | 作用 |
|---|---|---|
| `cooldown_seconds` | 300 | 触发后至少隔这么久，防暴涨时每 30 秒醒一次 |
| `max_triggers_per_hour` | **10** | ★ **这条最关键** |
| `poll_seconds` | 30 | 取价频率 |

**为什么每小时上限最关键：** 没有它的话，**最贵的时候恰好是行情最剧烈的时候** ——
价格疯起来它会不停地醒，成本反而**比固定心跳还高**。这个改动要省钱，
就必须在"该醒的时候醒"和"别被行情牵着鼻子跑"之间加一道闸。
超限时会发一条 `wake_capped` 事件，面板上看得见。

### 睡眠

| 配额 | 值 | 谁定 |
|---|---|---|
| 一天最少睡 | 6.5 小时 | `.env` 的 `SLEEP_MIN_HOURS_PER_DAY` |
| 单次最长 | 11 小时 | `SLEEP_MAX_SINGLE_HOURS` |
| 连续清醒上限 | 17.5 小时（= 24 − 6.5） | `SLEEP_MAX_AWAKE_HOURS` |

**睡眠期间定时唤醒全部静默** —— 这是省 token 的主要来源：
6.5 小时的睡眠里**零次 LLM 调用**。

只有两种情况能把它从床上拽起来：

| 触发源 | 睡眠期间 | 谁负责 |
|---|---|---|
| 定时兜底 | **静默** | 这就是省钱的地方 |
| 人类阈值 | 能叫醒（面板可关，默认开） | 人的判断，人负责 |
| 自唤醒 | **能叫醒** | 它睡前自己押的注 |

#### 被叫醒不影响睡眠债

**半夜被叫起来处理两次，早上照样得把 6.5 小时睡够。**
所以"自唤醒能叫醒睡梦中的操盘手"和"一天必须睡满"这两条能同时成立。

实现上就是：债 = `required(滚动 24h 折算) − slept(滚动 24h 累计)`，
被叫醒那几轮**不扣债务**，只是把 `awake_span` 归零重算。

被叫醒后**自动回到睡眠** —— 它不用再调一次 `sleep`。
上下文里会明确告诉它："**你是被叫醒的**，这一觉从 X 开始，处理完会自动回睡"。

#### 两条硬闸

```
连续清醒 ≥ 17.5h 且 debt > 0   → 强制入睡（d.run=False，不花 token）
睡眠中 sleep_hours ≥ 11h        → 强制叫醒
```

第二条不能省：**没有它，"自唤醒能叫醒它"会退化成"永远睡着"。**

债务需求按**进程首见以来的时长折算**（`sleep_first_seen`），
所以刚部署那一刻不会立刻背上 6.5 小时的债；跑满 24 小时才要求整额。

#### 睡前必须把止损设好（只警告，不拦）

`sleep` 工具入睡前会查一遍持仓，**没有止损就回一句具体的警告**
（点名是哪个币），但**不阻止入睡**。

理由：睡眠引入了本项目第一个「Agent 主动不设防」的状态。
先观察它会不会自觉，再决定要不要升级成硬闸。

**而且它敢睡的底气不在提示词里** —— `mcp-paper` 的后台止损巡视线程
每 30 秒跑一次，**跟它醒不醒完全无关**。这是代码保证，不是纪律。

### ★ 睡眠账本为什么在 mcp-paper 的 SQLite 里

这一条是这次改动里最重要的架构判断。

我最初打算放 `/data/logs/sleep.json`，理由是"工作区外，Agent 够不着"。
**这个前提是错的。** 实测：

```
uid=10001(trader)              ← 和 brain 进程同一个 uid
/dev/vda1 /data/logs ext4 rw   ← rw 挂载进 brain
能读 journal.md
能不能写 /data/logs ? → 能写！
```

`run_shell` **只锁了 cwd，没有 chroot**。所以：

> **brain 能写的地方，Agent 都能写。**

配额放那儿，它一句 `python3 -c "..."` 就把债务清零了 ——
"一天最少睡 6.5 小时"会变成一句客气话。

`data/db` 是**唯一没挂进大脑容器**的目录。所以：

```
风控参数在那儿 → 睡眠配额也该在那儿
```

这不是保密，是物理隔离 —— 它连文件都看不到。新增三个 MCP 工具
（`sleep_state` / `sleep_start` / `sleep_end`），配额参数走 `SLEEP_*` 环境变量，
和 `RISK_*` 并排。

> ### ✅ 同一处事实顺手堵上了那个洞（2026-09-27）
>
> 当时 `run_shell` 能读 `/data/logs/`，所以**叙事层的「单向性」在 shell 这条路上是漏的** ——
> 它一句 `cat /data/logs/journal.md` 就把叙事层的输出读回自己上下文了。
> 也就是说第十三节那句"手账刻意放 logs，因为工作区是 Agent 能 `fs_read` 到的地方"
> **当时只是约定，不是物理保证**。
>
> 现在它挂上了 **Landlock**（内核 5.13+，非特权 LSM）：exec 子进程前用 ctypes 挂一套
> 文件系统规则，把它锁死在工作区，`logs/` 和 `/proc` 都在名单外。
> 查这一步时还挖出另一个更严重的：`/proc/<pid>/environ` 里的明文密钥。
> 完整设计、白名单、以及那个改不掉的 `getattr` 缺口见第六节。

### Agent 拿到的三个新工具

| 工具 | 作用 |
|---|---|
| `sleep(reason)` | 去睡。睡前自动查持仓并警告裸奔的仓位 |
| `wake_up(reason)` | 主动结束睡眠（自然醒）。被叫醒不需要调它 |
| `set_wake_policy(interval_minutes, thresholds[], clear)` | 改自己那份策略 |

**钳位规则：人类的值是上界，Agent 只能往短里改。**

这一条必须有。否则"人和 Agent 都能改间隔"会变成"Agent 可以给自己放假到明天"——
兜底的"最长沉默"承诺就被它单方面作废了。下限 5 分钟（再勤快就是烧钱不是盯盘）。

`thresholds` 是**覆盖式**写入（不是追加），所以它必须一次列全；
传 `clear: true` 清空全部自唤醒规则。

### 面板

右栏新增「**唤醒策略与睡眠**」卡片：间隔 / 上限 / 冷却 / 阈值可直接改
（写进 `/data/logs/wake_policy.json`，下一次判定生效），
规则表把**人类的（标"人"）和 Agent 的（标"自"）并排显示**，
底部是按触发源的统计。顶栏多了睡眠胶囊。

**这一行是用来读病的**，和 `并发 0/3 · 上轮取数 1 · 委派 0` 是同一个道理：

| 看到什么 | 说明该做什么 |
|---|---|
| 定时占绝大多数、价格触发长期为 0 | 兜底间隔还能再放长 |
| 自唤醒很频繁 | 阈值太敏感，它正在烧钱 |
| 睡眠时长为 0 | 配额没生效，去查 `mcp-paper` |
| 「⚠ 睡眠账本不可达」 | `mcp-paper` 挂了，调度按"清醒"降级 |
| 出现 `wake_capped` | 撞到每小时上限了（这通常是好事，说明闸门在工作） |

### 叙事层怎么配合

| 时点 | 叙事层 |
|---|---|
| 睡前 | **自动出一篇**（`sleep_start` 进了 `_NOTABLE`，当场触发）。写他为什么现在睡、睡前把哪些止损钉好了 |
| 睡眠中 | **不写** —— 面板上挂睡眠指示就够了。中途写一篇"还在睡"纯烧钱 |
| 醒后 | 下一篇素材自然横跨整夜，写出来就是"睡了一觉起来，盘面变成这样" |

`_digest` 会把 `sleep_start` / `sleep_end` 翻译成素材行（带债、已睡、清醒时长），
叙事层的 system prompt 里也加了一句**"睡眠是他的正常作息，不是空白也不是故障"**，
并明确**不许编造梦境**。

**不额外烧 token** —— 睡觉本身不产生日志，只是给它一层叙事。

### 一个容易踩的部署坑

**先推文件、后重建，是两个必须串行的步骤。**
这次真踩到了：重建读的是**磁盘上当时**的源码，
如果 `push.sh` 和 `docker compose up -d --build` 并发跑，
烤进镜像的是旧代码，而 `docker compose ps` 看起来一切正常。

### C. 方法论小结（比上面任何一条都值得记住）

这个项目最贵的几个教训都不是技术细节：

1. **静态提示词说服不了模型，把实时读数摆在它眼前才行。**
   子代理用法写满一整节提示词 → 0 次使用；加上运行时计数提醒 → 同一轮就用了。
2. **口径错了，提醒就会变成噪音。**
   提醒按"工具调用总数"计数 → 一轮里 5 次调用有 4 次是躲不掉的琐务 → 每轮空响 →
   Agent 两轮就学会无视它。改成只看"取数次数"才灵。
3. **提示词自己的语感会渗进产出里。**
   用 9 条编号清单写的提示词，产出就像合规报告；跟模型说话，产出就像人话。
4. **"听起来漂亮的归因"必须核账。**
   我一度认定叙事层那 33 个 `$` 是抄了提示词里的坏样例，核完发现主因是模型自己生成。
   见第十三节。
5. **一个"没人用"的工具，坏掉是无声的。**
   `market__get_prices` 一直是坏的（参数里多一个空格就被 Binance 拒），
   因为 Agent 一直用一次性全覆盖的 `get_market_overview`，长期没人踩到。
6. **部署步骤必须串行。**
   先推文件、后重建镜像 —— 并发跑的话，烤进去的是旧代码，而 `docker compose ps`
   看起来一切正常。
7. **「约定」不能当「物理保证」用，而且这句话被验证了两次。**
   先是"手账放 logs 所以它读不到"（其实 `run_shell` 读得到），
   再是"密钥只在 brain 进程环境里"（其实 `/proc/<pid>/environ` 读得到）。
   两次都是同一类错：**隔离写在文档里，而挡在前面的那道墙其实没砌。**
   判断标准只有一个 —— 能不能指到一处**代码或内核**上的机制，并且**跑一次证明它真的在响**。
   这也是为什么沙箱的降级路径不允许静默：挂不上就必须在工具返回值里留下那一行警告，
   一层"以为自己被保护着"的沙箱比没有沙箱更危险。
8. **一个坏掉的安全措施，症状和"没配"完全一样。**
   `landlock_add_rule` 少传一个参数时，报的是 `EINVAL`，看起来像"规则不合法"；
   顺手把它降级掉，整层沙箱就静默等于没有 —— 而命令跑得一切正常，
   跑测试也全绿（因为测试没在测那个）。所以**红和绿之间必须留着"跳过"这个第三种状态**，
   不然你永远分不清"测过了"和"那段没跑"。

## 二十、公开只读页（2026-09-27，**已上线**）

> 这一节说明公开只读页的设计理念与安全隔离边界。

面板一直只有两种状态：**全锁**（有凭证）和**全裸**（凭证留空，中间件直接放行）。
2026-09-27 加了第三种：**公开只读** —— 没有凭证的人能看日志，别的什么都不行。

### 它能碰到的是哪几条路由

```
GET /live                        公开页本体（brain/static/live.html）
GET /api/public/events           历史事件（脱敏）
GET /api/public/events/stream    实时 SSE（脱敏 + 并发上限）
GET /api/public/market           行情现价 / 24h
GET /api/public/state            账户 / 权益 / 绩效 / 成交
```

> 路由白名单（`web.py` 的 `PUBLIC_ROUTES`）一共就这五条。

### 公开的那一份，削掉了什么

**判据只有一条**：这个字段让读者知道了"系统被设成什么样"吗？是 → 削；不，它说的是"刚刚发生了什么" → 留。

实现方式是 `web.py` 的 `PUBLIC_SECRET_KEYS`：**一份 30 个字段名的全局名单**
（`model` / `models` / `model_label` / `policy` / `thresholds` / `rules` /
`landlock_abi` / `shell_sandbox` / `non_dumpable` / `servers` / `path` /
`api_key` / `key` / `password` / `token` / `secret` / 睡眠配额那几个 …），
**不分事件类型**，出口过一遍就削掉。

| 出口 | 另外还削掉的 |
|---|---|
| `wake_policy_changed.policy` | 整份策略字典（阈值 / 兜底间隔 / 每小时上限 / 冷却）—— 这就是配置本身 |
| `system.model` / `system.servers` | 主模型名、MCP 服务器清单 |
| `subagent_start.model` / `model_label` / `parallel_batch.models` | 子代理白名单里的 id 和标签 |
| `system.landlock_abi` / `shell_sandbox` / `non_dumpable` | 沙箱模式与它挂没挂上（**这三个是上线当天从真实数据里漏出去之后补的**，见下） |
| `subagent_models_error.path` | 白名单文件路径 |
| `system.message` / 事件正文 | **保留** —— 那是人话 |
| `/api/public/market` 的 `ref` 与 `dev_from_ref_pct` | 阈值基准价 + 与现价的距离（这两个数合起来能把人类阈值反算出来；行情本身照给） |
| `/api/public/state` 的 `risk_limits` | 整个键（仓位上限 / 日亏熔断 / 手续费口径） |
| `/api/public/state` 的 `status` | 走**白名单**：`agent.status()` 有 17 个键，其中 `llm_model` / `persona` / `narrator` / `wake` / `subagent` 全是配置。白名单而不是黑名单 —— 以后长出新键，默认就是不公开 |

> ### ★ 为什么是"按字段名"而不是"按事件类型"（2026-09-27 上线当天改的）
>
> 第一版写的是 `{kind: (要削的字段,)}`。上线后第一次看真实数据就漏了三个：
> `沙箱自检` 那条 system 事件里带着 `shell_sandbox` / `landlock_abi` /
> `non_dumpable`（`.env` 的开关 + 安全姿态），而我只想到削 `model` 和 `servers`。
>
> **测试全绿、本机验过、md5 也对，但它是漏的。** 漏的原因不是不小心，
> 是**判据的方向错了**：泄漏是按字段名发生的，而事件类型会一直长 ——
> 枚举事件类型这件事永远会输。改成按名字全局拒之后，加一个新事件、
> 它顺手带上 `model`，这一层什么都不用改就已经拦住了。
>
> 并且补了一条测试（`test_public.py` 的 [11]）：用 `ast` 从源码里挖出
> **每一个** `bus.emit(...)` 的字段名（28 个事件类型 / 54 个静态字段名），
> 逐个要求"要么在允许名单里、要么在必须削的名单里"，**没分类过就红**；
> 4 处 `**xxx` 动态展开点手抄了键、站点数量本身也在守。
> 这条测试抓得到当初那个 bug（把旧实现装回去试过，那三个字段原样漏出）。

### 为什么不把 `index.html` 挖空

面板是一个两万行的单文件，里面混着唤醒策略卡片、工作区文件浏览器、留言框、
暂停/叫醒按钮、以及一堆只有人类该看的读数。做成"游客版"意味着**每次改面板
都要重新想一遍"这段游客能不能看见"** —— 而漏掉的表现是什么都不显示，不是报错。

改成**另一份文件 + 一个 `/api/public/` 前缀**之后，"游客能看到什么"这个问题的
答案就是：读 `live.html` 里那 4 个 `fetch` 地址，加上 `web.py` 里那 5 条路由。
一眼能看完，而且 `test_public.py` 会替你盯着（多一条路由就红）。

### 公开流的并发闸门

`PUBLIC_MAX_STREAMS`（默认 40）是**全局**上限，不是按 IP：

- 一路公开流就是一个常驻连接，而且它**不花一分钱 token** —— 从成本那侧完全看不出
  有人在拖它，所以这个闸门只能在这里做。
- 为什么不按 IP：服务器在 Cloudflare 橙云后面，nginx 看到的 `$remote_addr`
  是 **CF 边缘的 IP**。按 IP 限流在公网流量下会变成"所有访客共用一个桶"，
  比不限还糟。真要按 IP，得先用 `map $http_cf_connecting_ip` 把真实访客地址取出来
  （写法在 nginx 那份 conf 的注释里，要动 http 层，得重跑 `setup.sh`）。
- 满了返回 503，并明说上限是多少。
- 租约是**幂等 + 会自动过期**的（`PublicStreamLimiter`）。响应体一字节都没发就断
  的那种情况下，生成器的 `finally` 不一定跑 —— 靠时间兜底，不然攒够 40 次意外
  断开之后公开页就永久打不开了（重启才修得好）。

### 顺手修的一个放大问题

`_cached()` 原来只有 TTL，没有 single-flight：冷缓存那一刻十个并发请求会打出
十条一模一样的账本调用，而 **MCP hub 是单任务串行消费队列的** —— 游客的一屏数据
会排在心跳的工具调用前面，把交易挤到后面。现在每个缓存键一把锁，
等锁期间再查一次缓存，并发塌缩成一次取数。面板那边一并受益。

### 怎么验

```bash
bash runtests.sh public    # 枚举 app.routes 逐条匿名打 + 脱敏 + 并发上限 + nginx 对账
bash runtests.sh frontend  # 公开页的 JS 结构、DOM id、真引擎渲染（[13] 那一节）
```

`test_public.py` 的第 [1] 节是这份设计里最值钱的一条：**它不检查"我有没有记得加鉴权"，
它检查"匿名到底能碰到什么"**。白名单写在一个地方，字面清单手抄在测试里，
两处不一致就红 —— 所以"加了一条新路由，忘了想这要不要给游客"这件事，会被人替你想。
